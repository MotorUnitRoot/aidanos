# Forensics

This is a short pass over the jobs behind CRM, ERP, and project screens. The costume was dropped. The job was kept.

## CRM

Salesforce Lightning and tools like it put a person or a deal on a record page. The page has a highlights panel, a colored path, related lists, and an activity feed. The job is to see who this is, what state they are in, what is attached, and what to change. The waffle, the utility bar, the brand header, the highlights panel, and the Path chevron bar are costume. AidanOS keeps key facts, a person, a status, place crumbs, label chips, stage steps as words, fields, a lookup that commits a wiki link, a related strip, an attachment link, and one activity line. It refuses the chrome. A binary fact uses the existing checkbox. There is no standalone toggle.

## ERP

NetSuite-style work is a master record and its detail lines. A sales order has a header and a sublist of items. The job is to name the thing, enter amounts, and keep the lines honest. Portlets, dashboards, and a second database of lists are costume. AidanOS keeps labeled fields, money, numbers, dates, line items, a table head, and a validation line.

## Project tools

Jira, Linear, and Asana-style tools show one issue and a list of issues. The job is to see the work, who holds it, how long it takes, and what is next. Boards and timelines can wait. Swimlanes, sprint chrome, Monday rainbow ornament, left icon nav rails, and a second project database are costume. AidanOS keeps a list row, a child list of hanging lines, a filter chip, a duration mark, a progress count, and the same paper as the day.

## How a job is marked

Look at the tired person. What must they see, change, or connect?

If the Door, Today, and Plan library already names that job, the mark is Already.

If the job is needed for generated work and can live on Stoic paper with one serif and no second store, the mark is Keep. A child list is hanging lines or list rows. That is a composition of the existing library, not a new atom.

If the job is real but the form is not ready, the mark is Deferred. Board lane and Timeline view wait for a later mark. They are an optional later pack.

If the thing only brands the vendor, forces a second database, opens a theme shop, or asks for a new page shell, the mark is Refused. A standalone toggle is refused. A binary fact uses the existing checkbox. Path chevron bars, highlights panels, utility bars, console subtabs, avatar piles, App Builder card mosaics, floating action buttons, left icon nav rails, Monday rainbow board ornament, traffic-light status, and Lightning button brands never ship. Refused never ships.
